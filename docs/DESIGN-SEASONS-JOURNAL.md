# 설계: 계절 · 날씨 · 마을 일지 (v0.3)

작성 2026-11-26. 상태: 4a(계절)·4b(날씨) 구현 완료(실기기 확인 대기), 4c–4d는 계획.

## 왜 하는가

`GrowthRules.standard`에서 Level 3은 누적 6시간이고 하루 상한은 3시간입니다. **이틀째에 마을 성장이 끝나고**, 활동 시설도 각 45분이면 생깁니다. 첫 주가 지나면 새로 볼 것이 없어서, 화면 한쪽에 켜두는 앱을 꺼버리기 쉽습니다.

해결 방향은 성장을 늘려서 붙잡는 것이 아니라 **"오늘은 뭐가 있었지?"** 하고 볼 이유를 만드는 것입니다.

유지하는 원칙은 다음과 같습니다.
- 오래 켜두라고 압박하지 않습니다. 놓쳐도 불이익이 없습니다.
- 프레임마다 실행하는 로직은 추가하지 않습니다. 노드는 시작할 때 한 번만 만듭니다.
- 두 모드는 같은 스냅샷을 그립니다.
- 규칙은 Core(Foundation 전용)에 두고 Linux에서 테스트합니다.

## 결정 사항

| 질문 | 결정 | 이유 |
|---|---|---|
| 계절 기준 | 실제 달력의 기상학적 계절(북반구 3–5 봄, 6–8 여름, 9–11 가을, 12–2 겨울) | 사용자의 바깥 계절과 같아야 "같이 사는" 느낌이 납니다 |
| 반구 | 시간대로 추정하고, 설정에서 북반구·남반구·끄기 선택 | 위치 권한 없이 대부분 맞습니다. 틀리면 직접 고칠 수 있습니다 |
| 끄기 | "Off" = 항상 여름(지금까지의 모습) | 눈을 싫어하는 사용자도 있습니다 |
| 일지 언어 | 영어 (앱 UI와 같음) | UI 전체가 영어입니다. 현지화는 UI와 함께 따로 진행합니다 |
| 순서 | 계절 → 날씨 → 일지 → 봄·여름 아트 | 12월 1일 겨울에 맞추고, 홍보 영상 소재로도 씁니다 |

## A. 계절 (4a)

### Core
- `Season` (spring/summer/autumn/winter), `Season.at(date, hemisphere:, calendar:)`
  - 남반구는 6개월 차이로 계산합니다.
- `Hemisphere.guess(from: TimeZone)`
  - 남반구 시간대 표(Australia/, Pacific/Auckland, America/Argentina/, America/Sao_Paulo, Africa/Johannesburg, Asia/Jakarta 등)에 있으면 남반구, 나머지는 북반구입니다.
- `SeasonSetting` (automatic/northern/southern/off)
  - `AppSettings.seasons`에 추가하는 필드입니다. 관대한 디코딩으로 기본값은 `automatic`이고, 스키마 버전은 그대로 둡니다.
- `TownSnapshot.season`
  - Ambient·Town Mode·Capture가 같은 계절을 그립니다.
  - 날짜로 계산하므로 저장하지 않습니다.

### 아트 (팔레트 교체 + 눈 덮개)

| 역할 | 봄 | 여름 | 가을 | 겨울 |
|---|---|---|---|---|
| 땅 (`ground`) | 연한 새싹색 | 기본 | 올리브·마른 풀 | 눈(흰색·옅은 파랑), 진흙 섞인 길 |
| 나무 (`foliage`) | 잎 하이라이트가 분홍 꽃 | 기본 | 주황·빨강 단풍 | 짙은 상록 + 꼭대기 눈 |
| 건물·소품 (`structure`) | — | — | — | 지붕·굴뚝·우체통·울타리·바위·우물 위에 눈 |

- **눈 덮개:** 각 열의 가장 위쪽 불투명 픽셀(외곽선이면 그 바로 아래)을 눈 색(`*`)으로 바꿉니다. 행 데이터로 만들므로 모든 스프라이트에 쓸 수 있고, Python 프리뷰에서도 똑같이 재현됩니다.
- **텍스처:** 계절별로 캐시합니다(`이름@계절`). 계절이 바뀔 때 텍스처만 교체하고 노드는 그대로 둡니다. 여름 텍스처는 기존 이름을 그대로 써서 PNG 오버라이드와 호환됩니다.
- **제외:** 가로등(유리 픽셀이 덮임), 꽃·꽃밭·이젤, 장식 아이템(묘목 제외)은 바꾸지 않습니다.
- **미리보기:** `scripts/render-art-preview.py`로 계절 4종 프리뷰(`docs/season-preview.png`)를 Linux에서 만들어 확인합니다.

### 개발 도구
- Developer → Demo: Season(Real calendar / 4계절)
- Capture Studio: **E** 키로 계절 순환. 프리셋 6 "Winter night" 추가

## B. 날씨 (4b)

- 그날 날씨는 날짜와 마을 시드(`createdAt`)로 정합니다. 저장하지 않고 테스트로 고정합니다.
  - 약 5일에 하루, 몇 시간 동안 비가 옵니다(겨울에는 눈).
- ~~첫눈이 오기 전에는 겨울이어도 땅에 눈이 없게 할지 검토합니다.~~ 구현하지 않았습니다. 겨울 내내 눈 덮개를 유지해서, 날씨를 계산하지 않아도 계절만으로 모습이 정해지게 했습니다.
- 입자(비·눈·낙엽·꽃잎)는 시작할 때 20개 정도 만들어 둡니다. `ambientLoops`에 넣어서 동작 줄이기가 켜지면 멈춥니다.
- 주민 행동을 보정합니다(`ResidentBehaviorRules`): 비 오는 날은 산책이 줄고 집에 머무는 비중이 늘고, 겨울에는 일찍 귀가합니다.
- 구현하면서 추가한 것: 비 오는 날 주민의 노란 우산, 비에는 이벤트 중지, 눈에는 고양이만 중지, 흐린 날 색조.
- Capture Studio: **W** 키로 날씨 순환.

## C. 마을 일지 (4c)

```
Thursday, 26 November
· A stray cat napped by the mailbox.
· Pip and Juno chatted by the well.
· First snow of the winter!
```

- **기록하는 것:** 하이라이트만, 하루 최대 6줄입니다.
  - 이벤트(고양이, 여행자, 모임)
  - 레벨업, 새 건물, 새 주민
  - 첫눈 같은 계절 순간
  - 주민 대화: 같은 짝은 하루 한 번만
- **기록하지 않는 것:** Demo 상태, 앱 이름이나 사용 카테고리. 일지만 보고 어떤 앱을 썼는지 알 수 없어야 합니다.
- **저장:** `town.json`과 분리한 `journal.json`에 최근 60일만 남깁니다(수 KB). 일지 파일이 손상돼도 마을 진행은 안전합니다.
- **보는 곳:** Town Mode 패널의 Journal 섹션, Ambient 마을을 클릭했을 때 나오는 말풍선의 오늘 최신 한 줄.
- **문장 생성:** Core의 템플릿 규칙으로 만들고 테스트합니다.
